# 구현 검토 기록

## 검토 기준

제공된 B2-1 필수 명세·평가표, 실제 코드, 표준 라이브러리 문서를 기준으로 검토했다. 1단계의 모델/검증 코드와 기존 40개 테스트를 유지·확장했다. 전체 기능을 처음부터 독립적으로 새 구조로 바꾸지 않고 그 모델을 CLI/서비스/저장소에 연결했다.

## 확인 및 보완한 사항

| 검토 관점 | 코드의 처리 | 검증 방식 |
|---|---|---|
| 최신순 정렬이 스트리밍을 깨지 않는가 | 저장 순서 유지, 조회 시 전체 리스트/정렬 없음 | 한 건 제한 이후 추가 읽기 금지, 반복만 가능한 스트림 |
| 수정한 날짜가 정렬을 깨지 않는가 | 원래 거래 제외 + 변경 거래 재삽입 | 앞/뒤로 날짜 이동, 무작위 변경의 기준 모델 대조 |
| 금액이 실제로 양수 정수인가 | bool 제외, 문자열 파싱과 값 검사 분리 | 0·음수·소수·잘못된 런타임 타입 |
| CSV 일부 반영이 발생하는가 | 모든 행 검증 후 한 번 교체 | 정상-오류-정상 행에서 세 파일 원본 비교 |
| CSV의 쉼표/개행이 데이터 손실을 만드는가 | csv 모듈로 열 해석, tags만 별도 분리 | 한글·따옴표·CRLF·여러 줄 메모 왕복 |
| CSV 내보내기가 원본을 덮어쓸 수 있는가 | 내부 경로, 실제 파일 동일성, 링크 검사 | 세 JSONL/lock 및 hardlink/symlink 차단 |
| 예산 표시가 큰 정수에서 float 오류를 내는가 | 정수 연산으로 0.1% 반올림 | 10**320 금액에서 100.0% 확인 |
| 저장 실패가 원본을 비우는가 | 동일 폴더 임시 파일과 교체 | write/fsync/replace/temp 생성 실패 주입 |
| 파일 일부 누락이 초기화로 은폐되는가 | 기존 내용이 있으면 유실 오류 | 거래 파일 제거 후 재생성 차단 |
| 지연 읽기 오류가 데코레이터 밖으로 빠지는가 | 실제 CLI 순회 경계를 감쌈 | 순회 중 OSError 주입 |
| 출력 파이프가 닫힐 때 종료 시 오류가 나오는가 | main에서 flush, BrokenPipeError 별도 종료 | 닫힌 stdout 파이프 실제 하위 프로세스 |
| 동시 프로세스가 덮어쓰기 경쟁을 하는가 | 배타적 파일 잠금 | 잠금 유지 중 별도 CLI 실행 차단 |
| 파일/잠금이 조기 종료 시 남는가 | closing 및 컨텍스트 정리 | 제너레이터 조기 close, 예외, 정상/실패 종료 |
| 타입 표현이 입출력 경계를 설명하는가 | Literal/TypedDict/Iterator/ParamSpec 및 검증 | 3.10 문법 검사, 값 검증 테스트; 정적 타입 검사 미실행 |

## 명시적으로 남긴 제한

1. 조회의 메모리 사용은 작지만 추가/수정/삭제는 O(n) 검사/재작성이다. import는 O(n+m) 메모리다.
2. 잠금은 협력하는 앱 프로세스 간의 단일 배타 잠금이다. 병렬 읽기 최적화, 자동 stale-lock 회수, 외부 편집 방어는 없다.
3. 원자적 단일 파일 교체와 정전 내구성은 다르다. 자동 백업·복구/저널/다중 파일 트랜잭션은 없다.
4. 조회 limit 뒤의 손상 행과 전역 ID 유일성을 조회마다 전부 검사하지 않는다. 거래 파일을 변경하는 add/update/delete/import 전에는 전역 ID 검사를 한다. 예산·카테고리 저장에까지 적용되는 검사는 아니다.
5. CSV 재가져오기는 새로운 ID로 중복 내용을 추가할 수 있다. 자동 중복 제거 및 ID 보존 복원이 아니다.
6. 실제 런타임 검증은 Linux / Python 3.13.5에서 수행했다. macOS/Windows와 Python 3.10 인터프리터 검증은 별개로 남아 있다.
7. 예상치 못한 오류도 성공으로 처리하지 않지만, 커밋 이후 화면 출력 실패 같은 상황에서 이미 완료된 저장을 자동 롤백하지 않는다.

검증된 범위에서 필수 기능의 남은 미구현은 발견하지 않았다. 이것은 가능한 모든 장애가 검증되었다거나 실제 피어 평가 합격을 보장한다는 의미는 아니다.

## 2026-10-09 재검토

기존 애플리케이션 소스와 테스트를 변경하지 않고 전체 테스트 175개, -S 실행, 실제 CLI 시연, 10만 건 읽기·쓰기 및 CSV 10만 행 가져오기를 재실행했다. 재검증 범위에서 추가 수정이 필요한 필수 기능 결함은 발견하지 않았다. README의 전체 ID 검사 적용 범위와 GitHub 반영/테스트 상태 표현은 바로잡았다.
