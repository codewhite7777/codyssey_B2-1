## 함수 주석 규칙과 결과

함수 정의 직후의 `"""..."""` 문서 문자열(docstring)에 기능과 처리 방식을 기록한다. 단순 함수는 한 문장, 파일 변경·지연 순회·예외 처리가 있는 함수는 필요한 사전 조건·부작용·실패 정책까지 설명한다. 내부·중첩·생성자·property 함수도 포함했다. 복잡한 지점에는 `#` 주석을 추가하되 모든 코드 줄을 한국어로 반복하지 않는다.

| 범위 | 설명이 있는 함수 / 전체 함수 |
|---|---:|
| 애플리케이션 | 79 / 79 (이전 18 / 79) |
| 테스트와 테스트 보조 함수 | 204 / 204 |
| 검증 도구 | 10 / 10 |
| 합계 | 293 / 293 |

개수는 AST의 def/async def 기준이며 lambda는 별도 이름 없는 식이므로 포함하지 않는다. 데코레이터 메타데이터 검사의 고정 `demo doc`은 검증 의미를 보존하기 위해 그대로 두었다. 설명 존재의 자동 검사가 내용의 정확성까지 증명하는 것은 아니므로 처리 분기와 함께 수동 검토했다.

주석 때문에 프로그램의 물리적 줄 수는 1,123줄에서 1,470줄로 늘었다. 이는 기능 확장이나 계층 증가가 아니다. 긴 표현 분해와 설명 보강이 목적이며 단순히 줄 수를 줄였다고 보고하지 않는다.

## 타입 계약 보완

기존 일부 함수는 `Iterator[Transaction]`을 받는다고 적었지만 실제로는 `closing`으로 `.close()`를 호출했다. 일반 Iterator 전체에 close가 보장되는 것은 아니므로 실제 사용 계약에 맞게 `Generator[Transaction, None, None]`으로 명확히 했다. 별도의 사용자 정의 프로토콜은 추가하지 않았다. 이 변경은 일반 반복자 지원을 새로 구현한 것이 아니라 원래 기대한 제너레이터 입력을 정확히 표시한 것이다.

타입 힌트는 런타임 검증을 대신하지 않는다. cast, dataclass frozen, 파일 원자성도 각각 다른 역할이다. 각 차이는 해당 함수 설명에 명시했다.

## 학습할 때 설명해야 하는 한계

list/search의 거래 순회는 스트리밍이지만 카테고리 목록은 메모리에 읽는다. limit 뒤의 손상은 해당 조회에서 발견하지 못할 수 있다. 전체 ID 중복 검사는 거래 변경 전에 적용되며 모든 조회/예산 저장에서 실행되는 것은 아니다.

추가·수정·삭제는 전체 거래 검사·재작성과 O(n) ID 집합 비용이 있다. import는 신규 m건 정렬과 기존 n건 ID 집합 때문에 O(n+m) 메모리를 사용한다. 월별 파일 분할·색인·외부 병합은 개선 제안일 뿐 구현된 기능이 아니다.

CSV에는 ID가 없어 재가져오기는 내용 중복을 추가할 수 있으며 자동 중복 제거·백업 복원이 아니다. 단일 파일 교체는 다중 파일 트랜잭션이나 정전 내구성 보장이 아니다. 자동 백업 명령·반복 거래·정교한 표 정렬·GitHub Actions는 필수 채점표에 없으므로 미구현만으로 필수 미완료나 감점을 단정하지 않는다.
